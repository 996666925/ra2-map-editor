## 创建地图

### 空白地图

通过“文件 → 新建地图…”或 `Ctrl+N` 创建地图。

| 参数 | 范围 |
| --- | --- |
| 宽度、高度 | 各 20～1004，且宽＋高不超过 1024；最大正方形为 512×512 |
| 初始高度 | 0～127 |
| 玩家起点 | 2～30 个 |
| 环境 | 温带、雪地、城市、新城市、沙漠、月球 |

尺寸与 VERA20k 扩展格网一致：宽＋高不超过 512 时保留原有 512 格网，超过时使用 1024 格网。

### 随机地图

在“文件”菜单中选择“新建随机地图…”。支持温带、雪地、城市、沙漠和新城市，以及群岛、大陆、海中岛屿、内陆湖泊和山地五种地貌。

宽高分别选择四档尺寸，窗口会显示由档位和玩家数决定的实际尺寸。支持 2～30 名玩家；超过 8 人时按玩家数量扩大地图面积，并为全部玩家生成起点、安全空地和资源。9～30 人的群岛地图生成多个大岛，让多名玩家共享岛屿。

可以调整水域规模、地形崎岖度、区域连通程度、树林数量、矿区分散程度和资源丰度，并开关矿区、宝石及中立科技建筑。水域等强度数值不等于最终占地百分比。群岛不使用水域规模参数，此时滑块禁用。

“区域连通程度”仅对内陆湖泊和山地生效，控制区域间坡道连接的尝试数量；0 也会尝试连接，不保证所有区域连通。“地形崎岖度”控制后期起伏，0～10 不增加随机高度扰动，但不会消除已有高台、悬崖或岸线起伏。“树林数量”为 0 时仍可能有矿树和地表斑块，温带中该参数还影响部分粗糙地表。“矿区分散程度”通常越大，矿区越多、单片越小，不直接调整玩家起点间距；关闭矿区后，矿区分散程度、资源丰度和宝石控件禁用。

“区域大小”仅对内陆湖泊和山地生效，范围为 0～100；数值越小，大块陆地区域越容易被切分。群岛的科技建筑按游戏规则尝试放在没有玩家起点的岛屿上；包括 9～30 人群岛在内，勾选后也可能没有符合条件的岛屿或成功放置的建筑。

生成器复用 VERA20k 的随机地图管线，包括随机地块生长、水域整形、岸线拼接、区域划分、起点选择、矿区扩散、山地与地表过渡、树林散布。生成在后台进行，完成后得到可编辑、待保存的新地图。

重新打开窗口会保留本次编辑器会话中的参数和种子，也可手工指定种子或点击“换一个”。切换地貌保留手调参数；点击“应用推荐参数”仅按当前地貌重设水域规模和地形崎岖度，其他参数和种子保持不变。相同版本、游戏资源、参数和种子可复现结果。缺少玩家起点的候选地图会自动跳过，最多尝试 16 次；地图的 `[RandomMap]` 节保存最终种子和完整参数，`EditorRequestedSeed` 保留最初输入的种子。若极端参数仍无法容纳全部起点，会提示调整参数或更换种子。

## 编辑地形

顶部工具栏提供常用工具，左侧显示参数与素材；地形按“地表、悬崖、水岸、道路 / 桥”分组。自动工具无需手工挑选地形素材，“手工拼贴地形…”可转入完整模板编辑。

一笔操作形成一次撤销。拖动时检查预览，松手提交，`Esc` 或右键取消，`Ctrl+Z` 撤销整笔。后台预览更新期间保留当前地图画面，准备完成后切换。

### 地表与框选铺地

- `B` 进入地形画笔，拖动连续涂抹。
- 地形、资源和覆盖物画笔按住 `Shift` 可锁定地图轴向：从起点沿较接近的地图轴移动，方向确定后保持锁定；松开 `Shift` 恢复自由绘制。拖动中再按 `Shift`，会从上一落点开始锁定。这里的轴向沿菱形格子的两条边。
- `G` 进入框选铺地；选择可平铺地表后左键拖框，单击只铺一格。
- 拖动时预览材质和格数，铺地保留每格高度。
- 橙色标出保留的坡道、悬崖、道路、水域和水岸；自动 LAT 的邻格过渡调整以浅蓝色显示。

### 悬崖、高台与坡道

手工选择完整悬崖模板时，默认用相对高度最低的有效子块对齐鼠标，切换上一块 / 下一块也采用该规则。未指定基准高度时，最低子块跟随鼠标下的地面高度；需要接续高台时，可以在锚点菱形中手动改选高侧子块。

点击画布上方“框架”或按 `Ctrl+F`，可切换类似 FA2 的框架显示：悬崖、转角和坡道使用简化素材，左侧完整模板、子块缩略图和放置预览同步切换，方便按形状拼接。框架模式保留高度和遮挡关系，对象、区域等编辑工具仍可使用。

“框架”和“2D 地形”互斥：开启框架会关闭 2D，开启 2D 会关闭框架；关闭当前模式后返回普通立体视图。游戏目录或其 `FinalAlert2` / `FinalAlert2YR` 子目录存在 `marble.mix` 时，使用其中与当前地形几何兼容的 FA2 框架素材和高度图；其他地形自动生成简化外观。切换显示不会改变地图中保存的地形编号和高度。

点击画布上方“2D 地形”或按 `F2`，可将地形铺平编辑。这个视图保持菱形格子的方向，去掉高度造成的屏幕位移，方便对齐悬崖的背面、转角和相邻模板；地图实际高度保持不变。再次按 `F2` 返回立体视图检查崖壁外观。

- 关闭框架时，格子颜色表示高度，悬崖为棕色，水面为蓝色，道路为灰色。放大后显示实际高度，数字后的 `/` 表示坡面；开启框架后显示简化地形素材。
- 金线标出相邻格子的高度变化，蓝线标出完整地形模板的外沿；进一步放大可看到模板编号和子块编号，方便配合左侧素材库手工拼贴。
- 完整模板、子块、升降、平整，以及高台、悬崖轮廓、坡道、水岸、道路、桥梁的自动工具均可使用。绿色预览显示修改格子，红色提示无效位置；松手提交，`Esc` / 右键取消，`Ctrl+Z/Y` 撤销与重做。
- 红叉表示对象占地，红点表示覆盖物。2D 是地形工作视图；选择对象、区域、资源等其他工具时自动返回立体视图。
- 右侧可关闭高度数字或模板边界。平移、缩放、地图导航、`Home` 适应地图、`F` 定位所选格子继续可用；拖动期间不能切换视图。

建议先在 2D 视图用 `C` 围合悬崖、`H` 生成或扩建高台，再用坡道工具补入口；需要精细拼贴时选择“手工模板”，根据模板边界对齐，最后切回立体视图检查效果。2D 的颜色和轮廓用于编辑几何，地图保存与导出仍使用真实地形。

使用“围合悬崖”（`C`）描绘轮廓，或用正面 / 背面悬崖画线；用矩形高台（`H`）扩建，再插入坡道入口。悬崖和坡道支持最高 127 层的正高度，标准悬崖高差为 4 层，低地基准可指定为 0～123 层，也可从已有地形自动识别。使用“坡道入口”时，在直线悬崖边缘按住左键，沿边缘向任一侧拖动即可加宽；宽度按完整地形模板吸附，松开后一次生成，可整笔撤销。点在矩形高台角落时，会将拐角本身转换为向外下降的连续坡面，并衔接两侧悬崖；沿任一地图轴拖动可加宽对应一侧的坡面。直边与拐角坡道相接时，同高度、同坡向的入口会自动合并，去掉连接处的收口；保存重开后也可继续从已有入口拖动扩展。

### 水域与岸线

矩形和围合水域会自动拼接岸线。环境提供对应地表素材时，还会补齐沙滩外缘与草地之间的过渡，包含四边和转角。已有水域可用“修复岸线”补齐过渡，邻格修改与水域一起预览并整笔撤销。

围合水域遇到无法拼接的一格斜边或细小折角时，会按 2×2 格向外规整轮廓，每轴最多补一格；可直接拼接的轮廓保持原样。拖动时显示实际生成的水面与岸线，松手提交预览结果。

### 桥梁

“架设桥梁”提供混凝土、木质的高桥与低桥。

| 桥梁 | 适用地形与要求 |
| --- | --- |
| 悬崖间高桥 | 从一侧高地或悬崖拖到另一侧，端点自动贴合崖边；两岸等高，桥下低 4 层，可为陆地或水面 |
| 水面低桥 | 用于平地河流；两岸与水面等高，端点可落在岸边并自动向陆地接齐 |

拖动会吸附地图轴向，预览绿色时松手放置。低桥在跨水拖动时始终显示到鼠标位置的完整桥面，端点未接岸时为红色，接齐有效陆地后变绿。

桥头需有足够宽的平坦通路。已有对象、覆盖物、坡面和不兼容的地形会阻止放置，并提示原因。

## 放置对象与区域编辑

### 单击放置与拖动连刷

选中对象素材后单击放置，或按住左键沿地图拖动连刷；快速移动时会补齐沿途格子。同一笔按实际占地去重，遇到占用、越界或建筑高低不平的位置自动跳过。

按住 `Shift` 拖动可沿一个地图轴向连刷；首次移动确定方向后保持锁定，回拖可缩短当前线段，越过起点可反向绘制。地形和资源画笔也支持这种伸缩操作。松开 `Shift` 保留当前线段并恢复自由连刷。拖动中按下 `Shift` 会从上一落点开始锁定，之前刷过的部分会保留。离开地图画布后重新进入，会从新位置继续，不跨越画布外的间隔补刷。

对象类型、所属方、步兵子格和重叠选项以按下鼠标时为准。拖动中显示对象预览，松手提交；`Esc` / 右键取消整笔，`Ctrl+Z` 整笔撤销。

### 选择与区域操作

按图层选择区域后，可复制、剪切、粘贴、移动或删除；区域选择时使用 `Shift` 添加、`Alt` 减选。对象可通过 `Ctrl+D` 克隆；复制、剪切、粘贴和删除快捷键见 [常用操作](../README.md#常用操作)。

### 开局交给起点玩家

选中建筑、车辆、步兵或飞机，在对象属性的“开局交给”中选择“航点 N 的玩家”，即可在开局转交给使用该起点的人类玩家或电脑。

- 支持地图上已定义的航点 **0～29**；8～29 为 VERA 扩展起点，需在“设置 → 地图信息”中配置相应出生点数量。
- 启用后初始所属方设为 Neutral（中立）；目标起点无人使用时保持中立。
- 选择“保持所属方”可取消转交；恢复启用前的所属方请使用撤销。
- 自动维护标准地图触发器，多个对象可交给同一起点，修改和取消支持撤销，并随地图保存。

对象已有自定义关联标签时，请通过任务触发器配置，避免覆盖原有行为。

## 地图与任务设置

### 表单输入与自动生效

对象属性、任务参数和光照在结束输入后自动生效：文本按回车或移开焦点，数值拖动松手后生效，勾选和下拉选择无需额外确认。每次完成的编辑可撤销；无效输入留在表单中提示，可修正或取消本次输入。

对象类型、所属方和任务引用字段支持输入补全，可搜索 ID 或显示名称。使用方向键选择，`Enter` / `Tab` 接受，`Esc` 关闭候选；仍可手工填写模组扩展值，也可使用原有下拉列表。

`Ctrl+S` / `Ctrl+Shift+S` 会先提交有效输入，再保存 / 另存。无效值与未应用的尺寸草稿会阻止保存。输入框保留自己的文字撤销、复制和粘贴操作。

自动生效写入当前地图文档，保存到磁盘仍需 `Ctrl+S`。地图尺寸裁切需检查预览并确认应用。

### 地图名称与出生点

在“设置 → 地图信息…”中修改地图名称、作者署名、开局基地车和出生点数量。

新建地图时可填写作者署名，也可留空。署名支持中文，最多 127 字节。地图信息中的“开局有基地车”默认开启，保存为遭遇战开局基地设置；启动器或房间设置可能覆盖它，不影响手动放置的单位。

地图名称支持中文，不能为空，最多 120 字节，不能包含分号或控制字符。按回车或移开焦点后自动生效，支持撤销、重做和保存前提交。

出生点数量可设为 2～30 个。增加时补齐缺少的起点并保留已有位置，减少时删除多余出生点；其他任务航点保留，可用航点工具调整位置。

试玩支持普通地图的航点 0～7 和声明的 9～30 人扩展起点。传统预览沿用引擎的八个起点标记，只绘制航点 0～7。

### 箱子规则

“设置 → 箱子设置…”可单独调整当前地图的箱子规则，包括数量上下限、随机刷新间隔、效果范围和单人金钱奖励。

| 设置 | 行为 |
| --- | --- |
| 最少和最多数量相同 | 指定开局箱数，实际数量还取决于可放置位置 |
| 最多数量为 0 | 禁止开局随机生成 |
| 刷新间隔 | 单位为游戏分钟，越小刷新越频繁；未拾取箱子约在 0.5～2 倍间隔内随机换位，拾取后尝试立即补充 |
| 字段留空 / 全部继承游戏或 Mod 规则 | 移除地图覆盖，沿用游戏规则 |

遭遇战或试玩需同时开启“随机箱子”。修改结束输入后自动生效，支持撤销、重做和保存前提交。

### 任务制作

任务编辑支持 House、触发器、Tag/CellTag、变量、特遣部队、脚本、小队、基地节点与 AI 触发器。

也可从顶栏“TypeScript 任务”新建脚本，在外部代码编辑器中检查类型并保存。点击“刷新类型”同步地图引用提示，点击“应用到地图”转译、执行脚本、校验地图数据并整笔应用，然后使用现有的保存、试玩与发布流程。

编辑器内置 Rust SWC 转译器，运行不需要 Node.js 或 Deno。**类型检查由外部代码编辑器完成**，“应用到地图”不执行 TypeScript 类型检查。带中文注释的引用枚举、API、示例与限制见 [任务脚本说明](../examples/missions/README.md)。

在航点引爆武器可使用 `action.explosionAt(m.weapon(Weapon.Vulcan), at)`；先刷新类型并从 `map.generated.ts` 导入 `Weapon`。该动作读取武器伤害和弹头，直接造成范围伤害，不发射弹体。只需创建动画时使用 `playAnimationAt(m.animation(Animation.EXPLOSML), at)`。体素碎片动画使用独立的 `action.playVoxelAnimAt(m.voxelAnim(VoxelAnim.TIRE), at)`；刷新类型后从 `map.generated.ts` 导入 `VoxelAnim`，其中成员来自当前规则的 `[VoxelAnims]`。

小队行为支持 `order.startLightningStorm(frames)`、`order.stopLightningStorm()` 和 `order.scoutHouses()`。前两项请求开始或结束全局闪电风暴，开始时间按有符号逻辑帧传入引擎，随后推进脚本。`scoutHouses()` 选择 House 建筑并移动、抵达后记录已侦察，支持多人；它与仅单人可用的 `order.scout()`（按玩家迷雾选点）含义不同。

小队气泡使用 `action.talkBubble(team, 1)`，可选图形编号1～3；全局只能显示一个，`clearTalkBubble()` 清除。小队必须已有活动实例，资源安装须提供 `talkbubl.shp` 和 `palette.pal`，也可通过 `m.asset()` 发布图形。气泡按墙钟超时，不用于显示自定义文本。

脚本可通过 `action.centerCamera(航点, 速度)` 平滑移动镜头；速度支持 0～4 档，默认 1，数值越大越快。`action.jumpCamera(航点)` 立即跳转，`action.homeCamera()` 返回本地基地。速度档位不是持续秒数，无效值在构建时会被拒绝。

持续定时出兵可使用 `when: event.sinceEnabled(30)` 和 `once: false`，每隔 30 个游戏秒触发增援；完整代码见 [重复增援示例](../examples/missions/README.md#每隔-30-秒增援小队)。

要在右下角同步显示时间，可用 `action.setCountdown(30)` 启动任务倒计时，再通过 `event.countdownElapsed()` 触发增援和下一轮倒数。也支持 CSF 标题、停止/继续及增减时间，见 [任务倒计时示例](../examples/missions/README.md#在右下角显示出兵倒计时)。

SDK 也支持规则启停/强制触发、原生多条件 `all()`、一次性分支 `any()`、全局变量与已有局部变量引用，以及对象/格子/小队共享 Tag。条件组合和原生锁存的边界见 [规则启停与条件组合](../examples/missions/README.md#规则启停与条件组合)，绑定方式见 [共享 Tag 与绑定](../examples/missions/README.md#共享-tag-与绑定)。

## 保存与恢复

`Ctrl+S` 后台保存当前地图，并生成内嵌 `PreviewPack`；保存后会重开校验，保留最多三份 `.yr-editor-*.bak` 备份。已有内嵌预览会在重新保存时更新。

空闲后自动生成恢复快照。Windows 默认位置为：

```text
%LOCALAPPDATA%/ra2-map-editor/recovery/
```

恢复后需要手动保存。

## 预览与图片导出

### 地图导航与内嵌预览

右上角“地图导航”与保存时生成的内嵌预览直接显示同一张引擎传统预览，包括地形、覆盖物和树木的预览色，以及红色方块起点。不会叠加编辑器的资源圆点、对象圆点或黑底编号。导航点击会按目标格高度定位到画布，矩形框表示当前视口。

- 传统地形由 VERA20k 的 `rmg::preview` 生成，尺寸由可玩区域的投影范围决定，每格贡献两个横向像素。导航与内嵌 `PreviewPack` 共用此图及标记，不包含导航视口框。
- 覆盖物颜色来自引擎的 SHP 帧头与规则，资源按密度着色。桥梁和树木也走引擎预览路径，不使用编辑器的替代色。
- 传统预览不受编辑器图层开关影响；导航采用最近邻缩放，保留原始像素。
- 按引擎可玩区域裁剪；高台、悬崖和地形高度不会缩小取景范围。超过 12 级的高地使用引擎预览色表的最高档（12），地图高度本身不变。
- 批量发布使用相同的内嵌预览生成方式。

### 选择导出方式

以下入口均位于“文件”菜单。

| 入口 | 输出内容 | 尺寸与显示设置 |
| --- | --- | --- |
| 导出高清地图预览图 PNG… | 调用 VERA20k 实际游戏渲染器，生成整张地图的高清图，包含未保存修改 | 最长边 4096 像素；不受编辑器图层与光照开关影响 |
| 导出内嵌预览原图 PNG… | 原样提取当前加载地图的 `PreviewPack`，包含自定义图片 | 保留原始尺寸和像素，无需游戏资源；不包含未保存修改 |

高清预览在后台导出，使用试玩设置中的 `vera20k.exe`，要求引擎支持 `--map-picture`，并需要可用的 GPU。引擎在隔离进程中加载当前地图快照与资源，绘制整个相机可见范围；地图自定义预览图片中的文字、装饰等不会参与重新渲染。失败时保留独立运行目录的日志，已有 PNG 不会被失败结果覆盖。

未保存的修改不会更新已加载的内嵌预览。没有内嵌预览时，请先保存地图生成预览，再重新加载后导出原图。

## 在 VERA20k 中试玩

点击“试玩”，选择遭遇战或单人任务，并指定 `vera20k.exe`；也可通过 `--playtest-exe PATH` 配置。试玩使用包含未保存修改的当前快照，输出写入独立目录。

任务声明了自定义文本或媒体时，试玩目录下的 `assets/` 会合并原版资源与任务资源，游戏从该目录加载。原游戏目录不变；大型归档优先使用硬链接，跨磁盘时复制，因此准备试玩可能需要额外时间和磁盘空间。

### 窗口、显示器与分辨率

默认使用窗口模式，勾选“全屏”可全屏启动。连接多个显示器时，面板会显示“显示器”选项，可选择启动屏幕，默认自动跟随系统。

“游戏内分辨率”通过本次试玩的 `[VERA] Zoom` 设置内部渲染分辨率，按所选显示器的实际像素列出完整档位及对应宽高。窗口和全屏使用同一列表；分辨率越高，画面越小，可见地图范围越大。

最大分辨率对应原始像素大小，使用游戏现有缩放档位，不改变窗口尺寸。调整游戏窗口后，对应分辨率也会变化。

### 玩家与设置保存

支持 30 人的 VERA20k 可试玩最多 1 名玩家加 29 个电脑的地图。

试玩设置会随编辑器配置自动保存，重启后恢复游戏程序路径、显示器、全屏、分辨率、速度，以及玩家、电脑、难度和对局规则。通过 `--playtest-exe` 或 Mod 配置显式指定的游戏程序路径，优先于上次保存的路径。

## 字体与可访问性

界面按需使用系统字体补全中文、多语言文字和 Emoji；可通过 `--font PATH` 优先使用指定字体。

原生界面已启用 AccessKit，并为引用、数值和光照等表单输入补充可访问名称。

## TypeScript 文本、媒体和战役

`m.crateLottery()` 支持单人“建筑栏购买补给箱 → 选点放置 → Ctrl 强制攻击拆毁 → 在 `rewardAt` 航点随机获得车辆”。它生成原生存在/不存在触发器和奖励小队，不修改引擎与普通箱子奖励，不再需要拾取木箱。同一时间一座，奖励固定归任务玩家，短暂延迟后到达航点；示例仍用机枪碉堡外观。完整用法与限制见[补给箱示例](../examples/missions/README.md#购买补给箱建筑攻击拆开领取车辆)。

生成的 TS 战役可通过游戏正常的“Save Game / Load Game”浏览器保存和继续任务。已验证倒计时、活动小队脚本与重复增援规则在加载后继续；当前客户端使用 VERA 自有存档格式，真实联机不提供该存取入口，原版 SAV 兼容不在此范围内。

两栖运输船可使用同一组小队装载、移动和卸载命令渡水，详见[运输脚本](../examples/missions/README.md#运输脚本的满载条件)。`waitLoaded()` 等待类型容量全满，原版 LCRF、SAPC 和 YHVR 为 12 人；水域、海岸及两岸航点需在地图上正确安排。

`m.configureHouse()` 和 `m.createHouse()` 可用 `uiName: m.defineText(...)` 设置地图 House 显示名，用 `edge: HouseEdge.West` 等指定读取该字段的增援入场边缘。显式运输航点优先；当前战役保留该CSF元数据，但普通战役外交/简报/结算没有House名称列表，不能据此保证文字可见；多人参赛者仍用房间昵称或电脑名，Neutral/Special使用类型名。固定 House 的小队按有效 Country 归属，同国后续 House 无法由原生小队表达时构建会报错，详见 [House 示例](../examples/missions/README.md#house-显示名与增援方向)。

小队脚本可用 `order.playSound()`、`order.playMusic()` 和 `order.playMovie()`；它们均推进下一行，播放与恢复由客户端处理，详见[小队媒体示例](../examples/missions/README.md#小队声音音乐与影片)。

任务可用 `m.defineText('id', '中文内容')` 创建文本引用，传给消息或倒计时标题。媒体用 `m.asset('输出名', '相对入口目录的路径')` 声明；应用只修改地图，试玩/发布时统一校验和输出资源。影片字幕支持声明 `subtitlemd.txt`（带 BOM 的 UTF-16LE）；格式与战役雷达影片暂停用法见[任务示例](../examples/missions/README.md)。源码、SDK、资源或原生注册顺序变化后需要重新构建；任务窗口后台显示待构建状态，重开地图会恢复上次入口路径。

“战役目录与任务发布”中的“构建并发布 TS 战役…”读取 `defineCampaign()` 入口，先构建各关任务，再生成中文 CSF、战役目录及媒体。任一关卡失败不会发布半套文件。无窗口命令为 `ra2-map-editor campaign-build --game-dir DIR --script campaign.ts --output NEW_DIRECTORY`，与 GUI 共用实现。

战役生成的地图还保存所属关卡和战役入口。重开后重建当前任务，会沿用战役根目录以解析共享模块和关内媒体，并从战役声明恢复跳转字段；若已更换或移除该关脚本关联，需要重新构建整个战役。

单人开局可用 `m.configureSpecialFlags()` 设置伤害冻结、战争迷雾、矿车自动选敌保护、桥梁可破坏性和矿石增长／扩散；多人只开放地图控制的起始部队精英配置。两种模式均可用 `m.configureLighting()` 声明普通、闪电风暴和心灵控制器的开局光照及淡变间隔；光照分量使用地图比例值（1 表示 100%），配置本身不会启动超武。

胜利结算页可用 `m.configureRanking()` 设置三难度的基准秒数，以及达标/超时的标题和评语；中文文案用 `m.defineText()` 声明。用时等于基准时按达标处理，省略字段保留地图现值。完整接口、单位/模式限制和可复制示例见 [TS 任务说明](../examples/missions/README.md)；逐项实现与验收边界见 [扩展计划](mission-sdk-plan.zh-CN.md)。


奖励专用车辆可使用 `m.rewardUnit('prize', { base: m.unit(Unit.HTNK), name: '奖励天启', rules: { Strength: 1500, Speed: 8 } })`，再将返回值放入 `m.crateLottery(...).rewards`。它复制基础车辆的规则并生成独立类型，只改变抽奖奖励；普通天启保持原属性。完整分组属性示例见 [reward-unit/mission.ts](../examples/missions/reward-unit/mission.ts)。`rules` 是单位 RULES 字段，伤害、射程、弹头等武器字段需由已有武器定义提供；美术仍须引用已有 ART。每种特殊能力仍受原生机制与资源限制，单纯新增一个键不保证获得对应机制。构建后不需要为这个功能修改或重编引擎。
