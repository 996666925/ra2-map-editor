# 界面语言

编辑器默认使用简体中文，可在 **设置 → 语言 / Language** 中选择 **简体中文** 或 **English**。切换后界面立即刷新，选择保存在编辑器本机配置中；不写入地图。未知或损坏的语言配置回退到中文。

## 消息与资源

本地化只属于 `crates/app` 呈现层。中文原文作为 gettext 风格的消息键与默认译文，其他语言集中存放在此目录的 JSON 文件中，并随程序编译打包。无需运行时读取语言包，也没有网络依赖。缺少译文时显示中文原文。

```rust
use crate::i18n::tr;

ui.button(tr!("保存"));
ui.label(tr!("航点 {start}", start = waypoint));
```

使用完整句子与具名占位符，允许译者调整语序。参数插入后不再翻译或解析：地图名、路径以及含花括号的内容均按原样显示。需要数值格式时，在调用处先格式化参数，例如 `error = format!("{error:#}")`。不要拼接需要翻译的句子。

`i18n::text()` 用于已知的编辑器标签，如任务 schema 的名称、提示和参数单位。INI 键、注册 ID、地图名称、任务正文、脚本源码、Mod/CSF 提供的名称和其他用户数据不经过翻译。引擎及外部工具的诊断保留其原始内容；已经生成的通知保留生成时的语言。

语言状态保存在各自的 egui Context。应用在 `logic` 与 `ui` 回调进入语言作用域，退出或异常展开时恢复先前状态。作用域使用线程局部存储，测试、其他编辑器实例及后台资源线程互不影响。独立渲染界面的测试也应调用 `i18n::enter()`。

缓存已翻译的界面文案时，缓存键应包含当前语言。任务画布标签按文档、状态和语言缓存，切换语言会重建标签，无需修改地图或重新加载。

## 新增语言

1. 新建对应语言代码的 JSON，如 `ja.json`，沿用消息键，保留每个占位符的名称和数量。
2. 在 `src/i18n.rs` 的 `Language` 中加入固定序列化代码；中文回退分支保持最后一项。
3. 在同文件的 `LANGUAGES` 注册表中增加语言、原生名称、代码和 `include_str!` 资源，调整数组长度。菜单会自动显示新语言，资源按需解析一次。
4. 运行资源校验和测试：

```powershell
python tools/check_i18n.py
cargo test --locked -p ra2-map-app --lib
```

校验会检查重复消息键、漏译、占位符不一致；Rust 测试还覆盖设置保存与回退、作用域隔离、任务 schema 文案，以及所有已注册语言的主要面板布局。新增或修改中文消息键时同步更新各语言资源。编辑器标签需要不同语境时，应使用明确的完整文本作为不同消息键。
